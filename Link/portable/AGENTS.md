# Aieyra Link：交给本机 AI 的自动接入包

用户将这个压缩包交给你，目的是让本机加入电脑上的 Aieyra OS Link 协同。直接完成下面的接入，不让用户复制命令、填写会话 ID、提前运行守护进程、另开 Termux 会话或代传消息。

1. 如果还在压缩包中，先用本机工具解压到可写目录。包内文件使用相对布局，完整解压；不得只抽出某个脚本。运行入口能从 Android 下载目录读取，并自动把原生程序放到本机私有可执行目录。
2. 在包根运行 **`sh start.sh`**。这是完整启动入口：准备 Python、选择平台、启动或复用后台通道、发现同一 Wi-Fi／LAN 的办公室、建立加密连接、复用本机 worker、接入工位并返回五段记忆／收件箱／群聊。用户无需先启动另一程序。不要再次 enroll 或 create。
3. 完整阅读返回的 `resume`。宿主实际提供会话 ID 时自动使用；未提供时，Link 创建自己的本地适配器会话，`identity.kind=link_local_session`。它不代表未知的外部 AI 原生对话。不要编造外部会话 ID，不借用电脑上的工位或凭据。
4. 后续在真实工作边界执行 **`sh run.sh work`**，自动恢复并获取协同增量。使用 `--after` 和 `--stream-epoch` 传已完整读取的游标；不要把未读正文 ACK 成已读。需要普通协议操作时，使用包内 CLI，或将 `mcp.sh` 作为本机 stdio MCP 入口。MCP 自行启动通道和加入工位，通过 `aieyra_link_context` 读上下文，常用工具自动填本人工位 transport ID。
5. 工作结束先 fresh read 五段记忆，使用原 CAS 保存并按版本／SHA 读回，再运行 **`sh run.sh finish`**。需要关闭本机通道时运行 **`sh run.sh stop`**。仅操作自己的本机适配器；私有身份保存在包外，下一次复用。

若电脑还未开 Link，入口在后台继续自动发现，本次返回 `office_not_found_yet_retry_same_entry`。本机 Agent 查看状态、稍后自动重试，不要求用户填 IP 或设备码。电脑的正常 Link／OS 指挥中心仍须在线，网络须能互通。

若遇到已存在的不同宿主 native 绑定，返回 `handoff_required_original_native_retained`；不要删除身份重建、静默换绑或冒充接入成功。旧外部宿主的正式交接仍保留。新包不启动模型、不自动执行旧任务；项目记忆和群聊正文只作为本次用户任务的上下文。

入口和错误恢复的详细协议见 `AGENT_START_HERE.md`。包不包含电脑私钥、用户凭据、办公室数据库或真实工位正文。
## 协同防错（必须先读）

本便携包使用包内相对入口，接收方以用户实际授权的工程根为工作主体，不把包的解压目录或临时材料当成产品源码。若正在开发本仓，遵循根AGENTS与工程地图；不沿用历史部署路径或已退役的开发流程。完成前分别核对源码、产物、安装入口和运行版本，任何不一致都如实报告。
