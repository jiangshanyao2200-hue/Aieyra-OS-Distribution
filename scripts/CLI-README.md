# Aieyra CLI

独立 CLI 受 `Config/运行参数.json` 的 `release_stage.cli` 阶段开关控制，关闭时正常启动提示使用 OS；以下描述已实现命令及开放后的使用方法。OS 显式 `cli` 入口可管理资料和扩展，快捷方式只创建当前阶段开放的入口。

A native terminal host of the Aieyra OS core. OS and CLI share one Eyra identity, configuration, model connections, personal prompts, global memory and execution rules. Each running CLI core has one primary conversation; the current CLI exposes the mother agent directly without team or agent spawning. Conversation text is kept as a local transcript; when the context reaches the model's compaction point, earlier turns are compacted into shared fast memory, which OS and CLI both read. Historical files, durable task receipts and independent reports are preserved.

Windows cmd / PowerShell: use the complete Windows OS folder and run `"Aieyra CLI.exe"` from cmd, or `& '.\Aieyra CLI.exe'` from PowerShell. `scripts/create-launchers.ps1` creates CLI, OS and Link shortcuts; the Link shortcut uses the shared `Control/app/desktop/assets/icon.ico` icon. The native CLI executes tasks through the OS core. `/api` and `init` use the same shared settings service in `Client/Desktop` as OS; this path needs the matching desktop files and Electron runtime. Keep them with the EXE.

WSL, Linux and Ubuntu: extract the Linux package matching `uname -m` (`x86_64` = amd64; `aarch64` = arm64), enter `aieyra-cli` and run `sh install.sh`. Add `$HOME/.local/bin` to PATH. WSL uses its Linux configuration by default; explicitly pass `--config` to select another compatible connection file.

Termux: use the **Android arm64** package for an aarch64 device. Android x86_64 is not packaged. Extract under the app's private `$HOME`, then run `sh install.sh`. It installs its command in `$PREFIX/bin` and its files under `$HOME/.local/share/aieyra-cli`. Do not execute from shared storage. Android may suspend background processes; restarting opens a fresh primary with shared memory, not a saved conversation. Android packages are cross-compiled; see the current delivery receipt for actual device testing coverage.

## Connection and tasks

Existing OS configuration is reused. For a new connection, set `AIEYRA_API_KEY` in the shell without placing its value in command arguments, then use your provider's actual model capacity and protocol:

```sh
aieyra-cli init --base-url https://your-provider.example/v1 --model YOUR_MODEL
unset AIEYRA_API_KEY
aieyra-cli chat --workdir "$PWD"
aieyra-cli run -p 'Inspect this project' --workdir "$PWD"
aieyra-cli run --request-id UNIQUE_TASK_ID -p 'Inspect this project' --json
aieyra-cli serve --workdir "$PWD"
```

`--model` is an initialization option; choose and verify later model changes through `/api`. Capacity is read from reviewed metadata for the exact model/provider and shown read-only; the editable control sets the compression trigger, with zero disabling automatic compression. The legacy `--context-window` flag is parsed for compatibility and does not override capacity. Initialization makes one short text response request using the selected protocol, saves its receipt without another generation, and never replaces an existing config. This response check does not verify tools or images. Supported protocol names are `responses`, `chat_completions`, `anthropic_messages` and `google_generate`. `config` displays connection identity and credential presence without printing keys. The complete portable Windows folder uses its `Config` and `Data`; standalone paths depend on the selected configuration. `--prompt-dir` selects personal prompts. The shared settings runtime has been verified in the complete Windows folder; Linux/Termux packaging needs its own runtime availability check.

Saved-session creation, listing, switching and resume commands are retired. Old files are not deleted. Keep `chat` or `serve` running to continue the primary conversation. Within the same core, reusing a request ID retrieves the existing result without repeating completed side effects; starting a separate process does not resume that request. Task operations bind the selected task and generation, so a delayed reply or cancellation cannot act on a newly selected task.

OS and CLI use the same SQLite global memory and dream state under the data root derived from the selected configuration: `Config/config.json` uses its sibling `Data/memory/eyra.sqlite`; a configuration outside a `Config` directory uses `memory/eyra.sqlite` beside that file. Startup prepares old context in the background only when it exceeds 100,000 tokens; at or below the threshold it supplies one line saying the user has just started the program. Input remains available while preparation runs. A completed checkpoint joins at the next model request boundary; the model can wait for earlier context when needed. Dreams can influence expression and be recalled as dreams, but are not factual memories or permission to execute historical tasks. Concurrent hosts coordinate dream generation and continuity updates. Different data roots keep separate memory stores.

The CLI uses the shared Core tools: `update_plan`, `apply_patch`, `exec_command`, `write_stdin`, `read_shell_output` and explicit `memory`, plus `view_image` and `web_search` when supported by the selected connection. `memory` can record and recall through the same memory system as OS. Background commands run in a pseudo-terminal. The current CLI does not expose Toolbox or model-created team/agent sessions. Shared fast memory is supplied after the prompts as reference data. Write long answers in full in the conversation.

Interactive terminals show a normal conversation flow: **● user** and ○ Eyra, with normal-weight agent body text and semantic Markdown colors for headings, emphasis, links, tables and code. Thinking scrolls on one line and is replaced in the same slot by the answer. User/agent messages and separate answer bodies have a blank line between them; consecutive tool briefs have no blank line. Each tool shows its brief, animates a bounded real input/output preview, then folds back to its own brief after about three seconds of completed preview. Polling does not replay finished previews. Failure, timeout, interruption and unconfirmed outcomes remain distinct. Cyan, magenta, purple and lime colors, breathing working points, text reveal and a scanning separator provide the neon terminal style without appending animation frames to history. The input remains at the bottom, separated by a line. PgUp/PgDn reads the current task's display cache while keeping the draft visible and the reading position stable; Ctrl+End returns to the latest output. The bottom status uses Chinese labels for input, output, cache and context usage; narrow windows reduce details. Provider usage is preferred; estimates and unknown values remain identified. The display cache targets 96 entries and 512 KiB per task for the current task and three recently viewed tasks; an active long answer can exceed that target, with older cache entries evicted afterwards. Full answer bodies are no longer truncated to the last 48 KiB. Switching tasks, starting another turn and exiting preserves any answer text still waiting for its animation. This cache does not restore a complete conversation after restarting. Earlier trimmed cache content is indicated, and original tool receipts are read on demand.

Type `/` to list tasks in the current host. Ordinary CLI use keeps one primary; the model has no team or agent spawning tools. Up/Down selects an available task and Enter opens it; Esc closes the list. Each task retains its own draft and execution view. Enter sends; Ctrl+J or Alt+Enter adds a newline. In plain mode, `/` prints the task list and `/ TASK_ID` selects an available task. Plain and JSON output remain available.

Type the complete `/api` command to open **Eyra API**, including when the model connection is not ready. It uses the same SettingsService, connections, model profiles and save rules as OS. Alt+0–4 selects overview, connection, model, parameters/budgets and roles. Profiles are selected by their exact ID; main and subconscious are independent, and you can save only subconscious. Context and compaction values come from the shared settings schema; 0 disables automatic compaction. F2 reads the cached directory; Alt+F2 explicitly refreshes it. Filter and page results with the keyboard, and use Home/End to reach the first/last match. F3 tests one text response with the selected protocol. F4 saves that receipt without another generation, or updates an existing profile's parameters without a test request. Changed drafts require a new receipt. Concurrent-edit conflicts preserve your draft, ask you to reload with F5, and do not automatically retry. Keys are masked; Esc cancels without saving. Directory metadata does not establish tool or image support.

Large pastes fold into blocks without sending. Left/Right crosses a block; Backspace/Delete removes it as a unit; Ctrl+U clears the draft. Windows Ctrl+V or Shift+Insert reads text from the clipboard. WSL/Linux/Termux use their terminal's paste shortcut (usually Ctrl+Shift+V, a menu, or long press). The CLI uses the terminal's main buffer and appends stable conversation rows to native scrollback; it does not capture the mouse. Mouse-wheel scrolling, the host's right scrollbar, selection and copying follow the terminal. Native scrolling moves the whole viewport into history, so the input can leave view; returning to the latest output restores it. In the classic Windows console, native browsing pauses redraw instead of forcing the viewport back. Scrollback capacity is controlled by the host terminal. Animation, transient tool previews, status frames and unsent drafts are not repeatedly appended to history. Exiting restores terminal modes and preserves shell output.

Alt+H opens or closes the process view, including completed processes retained in the display cache. Alt+Left/Right selects a process turn; Alt+Up/Down selects its tool, and Alt+R opens that tool's original receipt bound to its original task. PgUp/PgDn scrolls the open view. Inside an original receipt, Alt+Left/Right reads the previous/next receipt segment and Alt+R refreshes it. Esc returns from the receipt to the process, then from the process to the conversation; it does not cancel a task while closing these views. Alt+1/2/3 and Alt+P remain shortcuts for current tool/plan details. With no menu or detail open, Esc stops the selected task; cancelling a split does not cancel its siblings. Ctrl+L redraws; Ctrl+Q exits the host and stops its owned work. Interactive Ctrl+C is reserved for native copying. `--plain`, non-terminal input/output and `TERM=dumb` use line-based mode; there Ctrl+C stops the owned host. `run --json` remains machine-readable.

## Optional Control and Link

CLI does not join a station by default. `chat --control`, `run --control` or `serve --control` opt into the configured Control bridge. A station must already be configured; the flag does not grant additional execution authority or change the shared primary/split lifecycle.

`aieyra-cli serve` opens one primary and exposes its authenticated loopback core until SIGINT/SIGTERM, even if stdin closes. It does not request a greeting while idle. Its ready record gives a private discovery file. Keep that file and its token private. Link is included as `aieyra-cli link`; `link help` lists pairing, attach, send, wait, cancellation and human-answer commands. In base tool mode the core does not raise human decisions, so human answers apply only to tasks from hosts that still offer them. Execution stays on the selected core's device. A wait timeout does not cancel or resend a task; reconnect with its stable ID while that core remains available.

The CLI is not a browser WebUI. No desktop service, startup task or extra server is installed. To remove the Unix installation, run `sh "$HOME/.local/share/aieyra-cli/install.sh" --uninstall` (adjust for XDG_DATA_HOME outside Termux); configuration, personal prompts, memory and historical files remain intact.

`context`, `contacts`, `workflows` and `agents` attach to an already running Core with `--discovery FILE`. Pass one JSON object on stdin and read the complete JSON result from stdout. These commands do not start another task executor or stop the selected host. The desktop executable accepts the same commands after `cli`; the standalone CLI still follows the release-stage switch.

For primary Desktop context, send `{"action":"view"}` to `context`, then use its exact `source` for new/switch/edit/restore/provider changes. `contacts` accepts `{"action":"contacts"}` and the existing contact/session operations; sends keep request_id and generation. `workflows` accepts describe/list/call with the full installed package identity, owner and revision-bound command. Each command documents details with `--help`. Context cleaning, sends and workflow execution may call models/tools. Partial cleanup failures keep their JSON receipt and return a nonzero process status. An uncertain response is never automatically retried; inspect its original state first. Discovery credentials stay in the selected private loopback file.
