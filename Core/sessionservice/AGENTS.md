# 会话归档与目录服务 · 工作协约

遵循[根协约](../../AGENTS.md)；当前职责与迁移边界见[工程地图](../../docs/工程地图.md)。本文件覆盖本目录中没有更近协约的自有子目录，测试、样例资产和第三方依赖不因此成为独立执行模块。

入口：[archive.go](archive.go)、[catalog.go](catalog.go)、[records.go](records.go)、[cleanup.go](cleanup.go)。

职责：实现共同档案追加、尾记录恢复、带类型的身份/版本目录、有界记录目录与原子快照、逐项可重试清理回执。主会话、联系人、任务、标准Agent、工作流及专职Agent的领域适配仍由 Core 根包授权。

依赖与接口：只消费调用者给定的根、身份、租约和公共契约；不能自行推断 Agent 或 Workbox 的权限。

资料与状态：JSONL 原文、检查点、目录指针及清理回执各有身份。上下文提供者只占自己的命名空间，不能拥有整个会话目录。

开发与验收：在 Core 执行 go test ./sessionservice、go vet ./sessionservice；使用工程外合成档案覆盖尾损坏、版本冲突、失败提交、逐项删除重试和重开不重放。

记录规则：主会话沿用v1目录及原字节摘要栅栏；AgentManager通过LoadRecordDirectory完整读取并验证父树后才恢复中断状态，任务记录上限64MiB。Workbox完整记录和轻量列表共用RecordFile，上限16MiB，ID及owner须匹配实际目录；领域schema与依赖仍由宿主校验。记录写入必须持有原有owner/state租约，原子替换允许Windows旧读者继续读完整旧快照。文件链接、坏JSON、超限或错身份均拒绝并保留原件；不另存一份可漂移的索引。

兼容与交接：拒绝未来 schema 和跨类型身份，失败保留旧指针及原件。共同存取不改变既有私人资料位置，不自动开放已退役入口；跨端管理与最终恢复复核仍须逐项验收。修改接口时一起核对调用者、交付清单和对应专题地图；未实际验证的范围保持未验，不以目录存在或安装成功代替运行验收。
