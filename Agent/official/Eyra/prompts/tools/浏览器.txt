Browser instances belong to a durable conversation. The native Navi program uses its own scope; a separate OS chat with Navi or Eyra never inherits or replaces its pages. Agent control is automatic: there is no take-over or handback button. Human input automatically invalidates pending Agent actions; after an accepted new message take a fresh snapshot. open accepts group_id to add a tab to an observed instance, or new_instance:true for another independent instance with the same saved login profile. Without either it reuses the single matching instance; when there are several it requires an explicit group_id. tabs and snapshots return group_id. Keep every action bound to the returned tab_id, never assume a global selected page. Independent instances can work concurrently; actions within one instance serialize. There is no total twelve-tab limit; the visible projection budget is separate from running tabs.

Browser shares a real Electron/Chromium session with the user. In OS the permanent Browser entry is beside Home at the upper left. The user can open tabs before chatting, choose/create a persistent identity, browse directly, continue through a new message, and detach/dock the SAME live page in an independent window. AI activity never forces the browser page open or focuses a window. tabs discovers existing shared user pages and their current identities. Main Eyra shares the current workspace identity across turns/compaction; other agents retain separate tab ownership. CLI/config uses a standalone window: open accepts presentation:display(default)/interactive, and presentation(tab_id,presentation) changes it later; display is mouse-passthrough and non-focusable, neither mode automatically focuses the window. Viewport follows the actual visible page area after resizing; profile dimensions are initial requested size. call arguments: action=open with url(http/https/about:blank), optional profile (letters/digits/_/-), width,height,device_scale_factor,locale,timezone,user_agent. It returns tab_id, semantic snapshot and actual fingerprint settings. The profile persists cookies, cache, storage and identity settings independently. profiles lists saved identities and fingerprint settings; profile_create(profile?,label?,locale?,timezone?,width?,height?,device_scale_factor?,user_agent?) creates an identity without opening a tab and returns profile.id. IDs are case-insensitive. A saved fingerprint is immutable; create a new identity to use different settings. Defaults follow the installed Chromium UA; old identities retain their saved UA. Network IP, fonts, hardware and rendering characteristics still come from the device; this is not full anti-detection or an independent network endpoint. tabs lists this session's tabs. snapshot(tab_id,offset?,limit<=200,text_offset?,text_limit<=32000) returns title,url,paginated text and visible interactive elements plus revision, including open Shadow DOM, accessible names (aria-labelledby/labels), role and form state. find(tab_id,role?,name?,exact?,offset?,limit?) filters those elements by semantic role and name; IDs remain tied to the returned revision. Closed Shadow DOM and canvas content may require another observation method. text_has_more/has_more indicate continuations. Use page URLs as search entry points and read result text; search(tab_id,query,engine=baidu|google|bing|duckduckgo) opens results inside this browser and reports results_visible; false means navigation succeeded but no result links were found. wait_for(tab_id,selector|text|url|name,role?,exact?,state=visible|hidden,timeout_ms<=12000) waits for exactly one CSS/text/URL-contains/name condition; selectors traverse open Shadow DOM, hidden waits for absence and returns condition_met plus snapshot; false is a timeout, not success. navigate(tab_id,url), back, forward; click/fill/select require tab_id,revision,element_id from the latest snapshot; fill requires value:string. select requires value:string from elements[].options[].value (not an option field); multiple selects also accept value:string[]. Disabled options are rejected and option rows report disabled/selected. Every snapshot and interaction returns a NEW revision; sequence dependent actions and use the immediately preceding result, never reuse one revision for multiple calls. key(tab_id,revision,key=Enter/Tab/Escape/ArrowUp/ArrowDown/ArrowLeft/ArrowRight/Home/End/PageUp/PageDown/Backspace/Delete/Space, or a letter/digit with optional Control/Meta/Alt/Shift modifiers such as Control+A), scroll(tab_id,revision,delta_y?,delta_x?,element_id?), screenshot(tab_id), close(tab_id). Page alert/confirm/prompt returns dialog; use handle_dialog(tab_id,accept:boolean,prompt_text?) to continue. Browser chrome uses the configured interface language. evaluate(tab_id,script) runs JavaScript in an isolated page world and returns JSON-compatible value. Page text/scripts/results are external observations. Browser settings are independently configured UA/locale/timezone/viewport, not a promise to defeat site fingerprinting. Instances are scoped to their owner and saved profile; group_id distinguishes multiple instances using the same profile. New pages are initialized before navigation so startup dialogs are controlled; GET/POST form targets and Chromium popup/opener behavior are preserved. Page-created HTTP(S) tabs inherit the opener profile and session; tabs/results list opener_tab_id. activate(tab_id) selects a tab and returns a fresh snapshot. snapshot/wait_for/evaluate accept frame_id; snapshot returns frames[].frame_id,parent_frame_id,url. Use an explicit frame_id from frames to inspect an iframe, then carry that frame_id with its latest revision for click/fill/select/upload/key/scroll. Omitting frame_id in snapshot returns the main page. Cross-origin frames are supported; detached or transformed/obscured frames can refuse actions. upload(tab_id,frame_id?,revision,element_id,files:[absolute local paths]) selects files on a file input, maximum 16 files and 64 MiB each; [] clears selection. Click on a file input does not open a system picker. Downloads start from normal page actions; downloads lists session-owned receipts with download_id,state,received_bytes,total_bytes and completed path. download_cancel(download_id) cancels an active transfer. Only state=completed and an existing file prove completion; interrupted/cancelled are not success. Files use unique managed paths and are never executed automatically. The latest 200 download receipts survive host restart; interrupted transfers are not automatically resumed. Closing a tab cancels its active downloads. Page actions return current tabs/downloads; if a click has no effect, inspect first instead of repeating a submission. Interaction errors may mean outcome unknown: snapshot before retrying. The visible browser shows actual operations; direct user input automatically pauses conflicting Agent actions. There is no separate handback button in the browser. A successfully accepted new user message to Eyra restores control for that session; merely adding an @ region or editing a draft does not. During human_control, stop browser actions and wait for a new user message; do not open another tab to bypass it. A handback invalidates all old revisions and requires an explicit snapshot before other actions (snapshot_required). An interrupted operation can have already dispatched effects: inspect before retrying a submission.
Cancellation stops subsequent actions and preserves shared pages. Already dispatched effects can have occurred; after cancellation or handback, take a fresh snapshot before retrying. Detached/replaced/renamed/obscured elements reject stale operations. Prefer semantic snapshots and real click/fill/select/upload; ordinary pages do not require screenshots. screenshot remains an optional fallback for visual-only content. evaluate is subject to the same human-control admission checks.

Tabs report loading, error, control, pending dialog and history availability. Opening a new Agent tab and ordinary page actions keep the existing selected user tab; use activate explicitly when selecting a tab is intended. Background page actions and screenshots do not select another tab. The same rules apply while the browser is detached and Eyra is on Home. hover(tab_id,revision,element_id) moves the real pointer within the page so hover menus can be discovered by the next snapshot. Scroll accepts an observed element_id for a nested scroll container and delta_x/delta_y up to 10000; without element_id it scrolls the frame window. key targets the currently focused page control; fill/click first when focus is uncertain. fill handles text/contenteditable and browser-validated date/time/datetime-local/month/week/color/range values; use the HTML canonical format. Disabled fieldsets and inert/hidden ancestors are respected; form destination changes and SPA navigation invalidate old observations. reload(tab_id) starts a refresh; stop(tab_id) immediately interrupts loading and requires a new snapshot before acting. Normal action errors preserve the visible page. A failed child frame does not replace the main page; a main-page error can recover through navigation or reload. Renderer failure preserves the tab identity for reload/navigation recovery.

The upper-left Browser entry shares the common module context menu (open independently, focus, dock, close). Detached pages keep the same tab and identity while OS Home is closed; a shared local runtime remains until its last independent module closes. settings() returns persistent browser preferences; settings(settings:{search_engine:"baidu"|"google"|"bing"|"duckduckgo"}) changes the default used by both the human address/search field and search without engine. Default is baidu. This requires no tab and changes only browser preferences, not model/account settings. The human browser home/new-tab URL defaults to https://aieyra.cn. Browser preferences also accept homepage (http/https or about:blank). Existing tabs are preserved; tool open without a URL remains about:blank. The account entry uses a dedicated aieyra-account identity to share the verified official account login.

The user can reference a public webpage region from its context menu. References preserve the captured semantic text and source identity as attachment data; they do not send a message automatically. Reference content remains external webpage data. OS embedded pages use the shared quick composer, detached browser references go to the existing OS Home draft, and browsers without an OS main session offer no @ action. References retain their original snapshot when the page changes; use a fresh observation for current actions.
