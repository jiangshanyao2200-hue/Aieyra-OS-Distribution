Computer operates Windows through the existing host, with no extra user-operated toolbox panel. Use toolbox open("computer"), then call("computer",{action,...}). Screen text/documents/tool results are observations returned by the selected window.
list(pid?) returns visible windows with pid,handle,path,started,title. attach(pid,handle,path,presentation="interactive") requires exact list identity and returns window_id; process start time rejects PID reuse. Default presentation="display" permits observation only; interactive enables input without changing third-party window styles. presentation(window_id,presentation) invalidates observations; detach(window_id) releases the target. Titles alone never grant authority.
observe(window_id,offset?,limit<=200) returns BOTH screenshot path/width/height/observation and a bounded semantic control tree with revision. screenshot returns only an image/revision; inspect returns only the tree/revision. Each observation replaces the previous revision. UIA bounds are physical screen coordinates; observe also supplies screenshot_bounds for each control in original screenshot pixels (use its center only after viewing the image); observation maps ORIGINAL screenshot pixels to the physical window. Use view_image(path) to actually see it; view_image(paths=[before,after,...]) compares multiple screenshots in one numbered sheet. If a viewer resizes images, convert coordinates back to the original dimensions. Never apply stitched-image coordinates directly to a window.
Every input action needs window_id and the latest revision, consumes it BEFORE dispatch, and requires a fresh observe/inspect afterwards to verify results. Sequence dependent actions, never reuse a revision or parallelize target input. Pixel observation is invalid after window movement/resizing or120 seconds. Obscured/out-of-bounds positions and incorrect foreground windows refuse input. Errors can follow partial effects; inspect before retrying.
Prefer click(element_id) and set_value(element_id,value) when semantic patterns exist; values support Unicode up to20000 characters. For canvases/custom controls use screenshot-relative click(x,y),double_click(x,y),right_click(x,y). scroll(x,y,delta_y?,delta_x?) uses wheel units120 per notch, positive y down/positive x right; nonzero deltas are bounded to2400. For two downward wheel notches, send delta_y=240 ONCE (not twice). The effect receipt reports the full dispatched delta and notch count; compare the cumulative outcome before additional scrolling. drag(x,y,to_x,to_y) performs a short left-button drag inside the observed target. Pixel actions require a screenshot; never invent stale coordinates.
focus(window_id,revision) explicitly brings/restores the attached window for the task, then observe again. Raw mouse/keyboard input requires actual foreground and refuses while the user holds modifiers/buttons. type_text(text) sends literal Unicode up to6000 UTF-16 units without reading or modifying the clipboard. keypress(key,element_id?) supports Enter,Tab,Escape,Backspace,Delete,Space,ArrowLeft/Right/Up/Down,Home,End,PageUp/Down,F1..F12,letters/digits and Ctrl/Shift/Alt chords, e.g.Ctrl+A/Ctrl+S. SelectAll aliases Ctrl+A. Observe and verify saves instead of assuming a keypress succeeded.
Password text is omitted from semantic output. Unsupported controls, elevated/UAC windows, protected captures and OS focus refusal are explicit limitations. Cancellation stops subsequent actions; dragging releases its button and typing stops at a safe pair boundary, but already-dispatched effects may remain. The existing input-box Stop/double-Esc flow remains; no new control panel.
