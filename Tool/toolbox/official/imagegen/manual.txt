image_gen is an on-demand Toolbox capability. Open image_gen, then call it through toolbox. Query models(category="all") for the complete configured model pool; never change the user's chat model. A single default image profile enables generation and editing automatically. Omit profile_id for that default; for a specific requirement select another available pool ID, even if its category is not image. Categories are hints, not proof of provider support. Unsupported image operations must report the actual provider error. Quality ALWAYS defaults to high: omitted/auto becomes high and PNG is requested. Never silently lower quality or resolution after an error. low/medium requires quality_reason quoting the user's explicit downgrade request. Requested quality does not prove actual sharpness or aesthetics; inspect the native result, never upscale and call it native high resolution.
action=generate/create/run/status/list/recover. generate saves a durable batch and runs a bounded group; create saves only, without provider calls. request_id (letters/digits/_/-,maximum96) identifies creation: repeating identical parameters returns the existing batch without charging, changed parameters fail. run/status/recover use batch_id. list discovers persisted batches with offset/limit after context loss. status reads progress while another call runs. run submits only prepared items; completed, failed and unknown entries never replay. recover repairs retained base64 output locally, or retries only the existing URL download after the original model/connection is verified unchanged and enabled; it never submits generation/edit requests. Downloads carry no provider credentials or cookies and never follow redirects. Missing/corrupt/expired receipts remain unresolved. Recovery updates the same original usage sample; accounting failure retains the paid response and any saved image, and subsequent recover only repairs accounting. After restart resume the SAME batch, never recreate uncertain work.
New batches use prompt+count(1..100,default1), or items:[{operation,prompt,profile_id,size,quality,quality_reason,images,mask},...] with up to100 distinct designs. Do not mix items with prompt/count. operation=generate/edit; prompt is complete and at most24000 characters. Items inherit omitted profile_id/size/quality/quality_reason from batch defaults. size=1536x1024(default),1024x1536,1024x1024,auto; choose composition deliberately and report real returned dimensions. concurrency=1..4(default1), max_items=1..20(default8) bounds each run. Long tasks continue in groups after reviewing receipts and output; generate only the requested total. No automatic endless creative loop. Use meaningful prompt variations when asked.
edit requires1..8 absolute local PNG/JPEG/GIF/WebP reference paths, each<=32MiB,total<=96MiB. Optional mask is a transparent PNG matching the first reference dimensions; transparent areas mark edits. Input hashes are saved at creation: changed references block resume. Prefer immutable attachment assets. Edit saves new originals, never overwrites references. Unsupported parameters or edit produce explicit errors, never silent downgrades or blind retries.
Results: batch_id,requested/submitted/completed/unsubmitted,state/recovery,items,paths/images and usage. offset(default0)/limit(1..100,default20),next_offset paginate; counts cover the batch, paths/images cover the page. OK may mean partial success. Each item has a stable request_id/state. Usage is reported tokens or unknown, not an invented bill. Accounting or persistence errors must not trigger regeneration. Original image bytes and dimensions are retained; raw HTTP200 responses are preserved before validation/saving for recovery. Generated-image metadata is stored per image without the old4000-image limit.
After each group use view_image(paths=[...]) for a numbered contact sheet. Check requested subjects/changes, composition, detail, text/hands where relevant, native dimensions and unwanted artifacts; technical receipt success is separate from aesthetic acceptance. Inspect a specific original detail only when needed. Without actual image input do not claim to have seen the pictures. Existing album/viewer/attachments display results; no new user-operated tool panel is required.

Muse uses its verified single-image URL protocol. The returned PNG/JPEG/GIF/WebP is fully decoded and kept as original bytes; actual format and dimensions come from the media, never the requested size. Muse editing is not verified and is rejected before submission.
