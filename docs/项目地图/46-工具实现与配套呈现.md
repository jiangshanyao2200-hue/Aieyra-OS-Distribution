# 工具实现与配套呈现

当前实际迁移包含补丁、终端、计划、看图、搜索、图片及视频工具箱的一次执行及其手册/输入/呈现。共同授权、进程、取消和持久提交仍由Core持有。工具不是只放一份说明，配套可视化与CLI文本回退同属能力及兼容条件。

| 位置 | 职责与真实消费者 |
| --- | --- |
| `Tool/base/official/apply_patch` | 补丁预检、上下文定位、写入与恢复；Core的tool_execution、orchestration调用同一执行器 |
| 同目录 `manual.txt` | 原有工具说明，编译嵌入，实际进入模型ToolDefinition；输入schema保持 |
| 同目录 `contract` | 输入与完整回执类型；Core保持兼容别名，执行器与文本呈现共用定义 |
| 同目录 `presentation/desktop.mjs`、`desktop.css` | 原有差异视图及样式；Desktop/stage注入共同活动状态和DOM能力，不另造执行结果 |
| 同目录 `presentation/text` | CLI只读回执格式；Client/CLI/terminal调用，不导入补丁执行器 |
| `Tool/base/official/terminal` | 动作/旧名解码、严格输入、手册、服务适配、完整桌面和CLI回执；Core保留PTY/进程/日志/恢复 |
| `Tool/base/official/update_plan` | 步骤/修订/依赖与计划快照规则及视图；Core持有授权任务和持久提交 |
| `Tool/base/official/view_image` | 读取准备、图片预算/拼图、schema/手册及事实；Core授权并保存不可变图片快照 |
| `Tool/base/official/web_search` | 工具schema/手册、原生/后备执行适配、有界Python桥和双端来源回执；`API/search`拥有供应商协议 |
| `Tool/toolbox/official/imagegen` | 生成/编辑规则、参考图与mask校验、一次执行回执、schema和默认手册；Core注入私有模型选择与持久化 |
| 同目录 `contract`、`presentation` | 原JSON图片/批次项契约、桌面事实与CLI完整文本；相册查看器继续共享 |
| `API/images` | 图片供应商协议、HTTP请求/响应、禁止重定向和无凭据下载，宿主提供图像校验 |
| `Contracts/protocol/accounting.go`、`image.go` | 公共用量/时序及图片供应商输入/不确定结果，不包含配置与凭据 |
| `Tool/contract` | 现有自建工具定义/版本、输入schema/参数与呈现校验；Core注册、加载、执行、活动投影真实消费 |
| `Tool/runtime/javascript.go` | 已校验动态包输入到受限JS cell；Core持久意图/授权/cell，不热载下载的原生Go |
| `Tool/presentation` | cards/table、完整JSON与CLI文本事实；宿主注入可信主题槽位，显示层不执行工具 |
| `Tool/workbox` | 工作流/绑定/步骤/审阅/恢复契约和视图；Core现有工具、图片批次和AgentManager实际执行 |
| `Core/tools/shell_guard.go` | 原命令误操作保护仍在Core；没有跟随补丁目录机械搬迁 |
| `Contracts/product-layout.json` | 交付清单包含Tool源码、手册、呈现和模块文件；构建自动发现Go模块 |

旧补丁实现和桌面/CLI里的同一呈现逻辑已移除。Core仍决定权限、调用身份、恢复资料位置、取消和持久回执。主题通过共同工具槽位与样式覆盖作用于视图，默认结构/层级保持。

依赖检查限制Tool只依赖自身和Contracts；工具呈现不能反向依赖Core、客户端或工具执行器。桌面语法、自测和UI协约继续覆盖迁出文件，不因目录变化降低检查范围。

生图持久批次/恢复和相册索引仍在Core。可导入Tool/Toolbox及受限运行时已接入共同包服务，工作流恢复、持久专职Agent与标准包组合已有实际消费者；见[地图51](51-可导入工具包与回执呈现.md)与[地图52](52-工作流与持久专职Agent.md)。原生绘制、视频和WebP能力分别验证；阶段开关保持实际配置，模块入口见[工程地图](../工程地图.md)。

官方工具共同登记：Tool/catalog.json → Tool/packages.go → Core/extensionhost/official.go → modules同一登记。Tool各能力目录native.json/manifest.json绑定原实现、手册和双端视图；Core/tool_official.go接入旧ID准入。ExecuteToolTurn读取既有回执后核新操作；编排cell固定准入快照，终端/看图/搜索/图片批次与Workbox各入口共用检查。基础工具仍使用原协议，第三方JS包保持版本化身份。验收见AIDEBUG official-tools-user与Core/tool_official_test.go，按对应构建保存实际结果。

Tool/toolbox/catalog.go与schema.go拥有14项能力的公开发现/服务归属与部分查询输入。Core/toolbox_discovery.go按实际调用上下文投影权限、宿主、阶段与停用恢复；显式open和call可在同一响应按原顺序执行，发现不会自动查询。私人手册及空覆盖仍热读，不写入open回执。完整构建及首次发现/同响应open-call/旧回执恢复GUI已验；14项是能力发现与服务归属，不是14个独立Mod，实际业务由Core、Program、Client等对应模块提供。

新增videogen：Toolbox的video_gen先create后submit，查询/离线恢复/下载分离；Core持久状态按会话寻址，API只处理协议与MP4检查。模型发现支持video类别，停用官方包不阻断原任务回执与结果取回，模型/连接停用仍阻断网络。验证进度见P7。

WebP图像识别由`Tool/toolbox/official/imagegen/image.go`与`Tool/base/official/view_image/prepare.go`接入同一Go解码器；先核字节/边长/像素预算再完整解码。Core保存实际MIME、尺寸、文件摘要与原始字节，不能按请求格式更名或伪造尺寸。官方载荷/手册变化必须同步manifest、提示词索引及公共隐私精确摘要。

首页共同只读投影：Client/Desktop/ui/work-surface.mjs的tools模式以完整调用身份选择默认2窗/最多12窗，原终端、搜索与差异renderer保持所属Tool实现；Tool/presentation/projection.mjs及projection.css提供Toolbox、项目、流程、协作、决策与媒体场景，客户端只注入Core核准的读取。显示不执行工具，隐藏不取消任务，完整回执沿receipt-reader分页读取；图片迟到结果按scope失效，外部程序投影分阶段接入。决策由共同ask-user接入原主输入框和原提交服务。实机工具执行与明确标注的合成只读视图分别由AIDEBUG core-tool-visuals-user记录。


浏览器/联系人新增共同只读投影，解析Core规范化tool/action及旧Toolbox envelope，宿主按原回执和源身份读取真实标签画面/公开目录状态；不得重执行或创建第二程序。见[一环运行与投影](../一环运行与投影.md)。
