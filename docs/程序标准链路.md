# 程序标准链路

新增程序先读[Program协约](../Program/AGENTS.md)、[一环运行与投影](一环运行与投影.md)和[长期协作开发](长期协作开发.md)。程序是“业务服务＋工具API＋持久Agent＋共同聊天＋窗口与预览＋实例归属＋背景投影＋完整生命周期”，不能只做一个页面。标准描述接入目标，某程序缺项须明确登记，不能把本规范当成已实现。

## 唯一链路与入口

| 能力 | 复用入口 | 新程序要提供或证明 |
| --- | --- | --- |
| 定义、操作与包生命周期 | [Program contract](../Program/contract/definition.go)、[SDK工具](../SDK/tools/AGENTS.md) | program.json/manifest、版本和依赖、实际操作声明、安装/启停/升级/卸载；精确摘要和原权限不放宽 |
| 人和Agent操作同一服务 | [Program runtime](../Program/runtime/desktop.cjs)、所属Program service | UI与工具API共同调用业务服务，真实读写和结构化回执；禁止另造模拟执行链 |
| 固定持久Agent及独立OS会话 | [program_agents.go](../Core/program_agents.go)、[program_agent_tools.go](../Core/program_agent_tools.go) | 原程序program_session、联系人新建OS sessions、模型/上下文/草稿/任务/权限各自绑定；角色定义与实例分开 |
| 聊天、决策与外观 | [chat-column](../Client/Desktop/ui/chat-column.mjs)、[program-agent-surface](../Client/Desktop/ui/program-agent-surface.mjs)、[layered-chat](../Client/Desktop/ui/layered-chat.mjs) | 复用完整聊天、Brief、历史、唯一输入/附件/决策、用户外观、展开/折叠和Halo；不得复制样式或第二聊天执行器 |

| 实例与并行控制 | [浏览器参考服务](../Program/official/browser/service/browser-runtime.cjs)、[browser-control](../Program/official/browser/service/browser-control.cjs) | 明确owner、实例、登录profile、动作串行及取消/快照代次；冲突时隔离，不抢其他会话实例 |
| 其他会话的背景投影 | [work-surface](../Client/Desktop/ui/work-surface.mjs)、[projection](../Tool/presentation/projection.mjs)、[浏览器平台桥](../Client/Desktop/host/browser.cjs) | 绑定真实实例/调用的只读呈现；前景聊天与背景工作分层，顶栏无额外工具标签页 |
| 隐藏、停止与资源释放 | 原服务、视图和AIDEBUG生命周期 | 隐藏停读/释放媒体，恢复读事实，不重复执行；停止、取消、解绑、卸载和迟到结果有原所属围栏 |
| 验收与证据 | [AIDEBUG](AIDEBUG.md)、[code-chains](../Contracts/code-chains.json) | 成功、失败、未知、取消、并行、100/125%、最小化、拆放及正常重开；真实回执、原生图和中间态分别核 |

## Navi的实例例子

在Navi程序内聊天，Navi直接操作其所属浏览器本体；不自投影重复卡片。在独立OS会话与Navi沟通，浏览器由该会话scope/owner分配，再把同一真实实例投影回会话。Eyra调用浏览器也沿该分配/执行/只读投影链。

优先复用已有实例必须同时满足：归属允许、没有并行任务冲突、显式实例身份可确认。原Navi正在工作或实例属于别的会话时，建立独立工作实例并投影，不能以“优先Navi”越过owner围栏。当前浏览器已经按会话scope隔离；不为了优化复用率把不同owner隐式合并。group_id指工作实例，profile指登录身份，owner指授权归属；有多个候选且未指明group_id就拒绝任选。同一实例串行，不同实例可并行；真人直接输入、旧快照和取消围栏保留。

Eyra调用联系人/设置等也应读取原业务事实。联系人目前是同源业务投影，原页面保留实际编辑入口；它还不是整页镜像或所有创建过程的实时可视化。设置目前有独立Sera和原生页面/共同聊天，不能从有页面推断每项修改都已支持同等投影。新增创建流程或完整程序投影时先补实际可读状态、owner和统一投影适配，再验证过程与结果；不复制表单或模拟成功来填标准。

## 每次接入的执行卡

1. 写需求原文、程序目标、复用链、所有者、数据/权限和验收表；对照上述十项，标明已有、待做、不适用及理由。
2. 从参考程序查真实消费者，尽量单文件承载一个职责；共享能力回到共同所有者，程序只保留业务适配。
3. 接入原契约、服务、工具、固定Agent、聊天、导航预览、窗口和实例分配；建立代次、取消、隐藏和错误路径。
4. 补原工具/程序回执的只读投影，按owner和真实实例读取；投影预算只约束显示，不应停止底层任务或夺取控制。
5. 更新就近AGENTS、代码链/目录地图、模块地图、精确交付文档和必要回归；签名包内容变更按原SDK维护版本/摘要及宿主准入。
6. AIDEBUG实际打开该程序和独立会话，做并行/冲突/取消/恢复及真实工具操作，集中收集问题，退出本人实例后统一修复；实际看图再记录接受。

这套标准和机器可查询的program_recipe供未来编程Agent复用，仍由同一个Core授权和提交；模板、静态地图、API 200或模型自述都不能代替实际运行验收。
