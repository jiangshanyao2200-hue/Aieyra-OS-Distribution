# Coding 领域模块 · 工作协约

遵循[根协约](../../../AGENTS.md)；当前职责与迁移边界见[工程地图](../../../docs/工程地图.md)。本文件覆盖本目录中没有更近协约的自有子目录，测试、样例资产和第三方依赖不因此成为独立执行模块。

入口：[service.cjs](service.cjs)、[coding.mjs](ui/coding.mjs)。

职责：Coding 是 Cota 主持、Vaya 按需调查与复核的固定工作模式。背景实时工作流只展开当前操作，前序操作收成最多两行；工具流随当前任务退出。上层使用与 OS 一致的透明全屏聊天，可折叠为左下头像及一句话状态。项目目录、文件文本、差异与历史在按需打开的项目文件窗口。默认只读，显式手动编辑，绑定与文件版本共同保护保存；编辑时暂停自动跟随。计划/报告仅在存在真实内容时出现。

依赖与接口：绑定、发送、停止和聊天分页都经宿主转给 Core 的受管 Coding 会话；页面不选择会话编号，宿主按当前绑定解析；项目操作使用宿主签发的绑定键，迟到草稿仅能保存到原项目私有草稿区。项目编辑器和共享工作投影各为独立区域。一个成员的连续终端调用共用只读记录，真实媒体按原调用授权读取，文件变更驱动编辑器跟随。聊天使用同一 chat-column 和 Halo。

资料与状态：会话、记录和成员配置归 Core 与联系人；本目录不保存凭据、模型密钥或会话副本。

Coding 属于当前 OS 一环。工作行与失败正文由共享聊天组件呈现；重试以 Core 保存的项目、成员身份与失败代次确认，显示名可以相同。正常用户消息按群规则交给主持或明确点名的成员，失败续轮回到出错成员。验收从顶栏进入，覆盖折叠、项目切换、保存冲突及重开。

开发与验证：按实际影响选择必要检查，复用仍适用的已有结果；涉及 Client/Desktop 展示或 Core 会话行为时，分别核对受影响代码与真实调用，不默认执行 syntax、selftest 或 Go 全套。界面变更按 docs/UI协约.md 核对受影响的实际功能；构建与 GUI 验证串行，实际验收期间所有受测源码冻结，实看所需原生图。

兼容与交接：关闭页面只释放展示，不停止正在进行的工作；取消、停用、卸载才按显式生命周期处理。修改接口时一起核对调用者、交付清单和对应专题地图；未实际验证的范围保持未验，不以目录存在或安装成功代替运行验收。

manifest.json覆盖本目录实际载荷；业务、页面或协约改动后使用SDK/tools/package.cjs的pack刷新清单，再重建宿主摘要。导航来自program.json，执行适配仍由宿主显式注入。

项目入口：原生目录/文件选择由宿主注入，用户明确打开后经Core coding_project更新实际工作目录；无模型也可人工浏览编辑。Ctrl+O打开文件、Ctrl+Shift+O打开项目、Ctrl+S保存。取消不切换；忙碌/待交付/未知终端任务阻止切换；旧草稿留在原项目。用户文件状态仅作为下次请求的数据，不自动发任务。背景消费 OS 壁纸与实际回执，长详情滚动，完整记录继续走同一授权读口。流程动画仅用位移和透明度，遵循减少动效。聊天默认折叠，头像、阅读区与输入沿公共layered-chat消费同一chatLayout。
