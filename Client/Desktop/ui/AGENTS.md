# 共同桌面视图 · 工作协约

左下浮动头像只占据自身的命中区域。联系人列表、终端等页面保持正常可用高度。以列表底边到窗口底边的实际距离、末行可达性及浮层旁可点击空间验收；色板要核实际着色与选中态、保存后跨窗口读取和窄宽度下的换行。

执行失败以 Core 同一主体、会话和代次的结构化回执为准。紧凑状态统一说“我们遇到了问题”，共享消息列展示脱敏详情及该回执允许的重试。已受理任务续轮、未确认投递核对、页面读取重试各自保留原请求身份。受影响入口须验证正文按钮、双击和切会话。自定义名字与状态用斜杠分隔，名字动画应用于实际姓名、避免发光并尊重减少动态效果。六项动效按真实等待、思考、工具和终态验证，存储成功只覆盖链路的一段。

工具可视化由动态标记与 Brief 构成顶栏，当前工具按实际输入、过程及回执自动呈现；压缩分别展示原文、已提交摘要与结果。首页/会话/程序投影共用setupToolWorkSurface。协作Brief通过linkMessageAuthor统一解析活动members及归档authors，席位释放后不得将历史姓名退回内部类型名；头像按相同修订缓存读取。

会话入口只收敛布局与显示轮数，不另定字体或固定头像。sd-name/cp-name复用chat-name，sd-last及cp-session的cp-desc按实际作者复用chat-text与eyra-text/user-text，文本覆盖沿原Theme区域目录；抽屉、联系人会话列和Brief共同消费由eyra-avatar派生的chat-small-avatar。检查实际字号、字重、行距、字距、阴影、头像及可读宽度，覆盖热更新、第二主题与正常重开；不能只查变量已继承或只查抽屉漏掉联系人会话入口。

所有聊天和投影消费同一chatLayout/appearance区域及订阅。折叠Brief直接复用setupChatColumn，保留真实身份、相对用户配置派生的小头像及同一文字样式；不再创建无头像WorkTranscript Brief列表或talk固定字号。当前思考/正文仍由共同WorkTranscript显示。协作Brief不是本轮最终答复，不能占用response显示ID。首页Core Link的邮箱逻辑代次不同于实际actor代次，须以公开actor_id/actor_generation和邮箱lead代次核对当前归属，不能互相比大小或取当前回合强贴旧消息。沟通原文仅供历史和原回执，实时显示作者Brief，缺省只显示真实类型状态。

阅读意图由chat-reading的createChatReadingIntent复用：只由实际垂直阅读手势暂停跟随，横向表格滚动和内部工作阅读不改历史跟随。主动发送须清除旧手势时窗与旧锚点；首页同时递增原生读位revision，拒绝迟到回执，原生消费者收到新revision也清旧时窗。仅把following设true仍可能被下一帧旧scroll关回false。普通快照/token不恢复跟随；程序Agent由真实发送信号显式恢复，不能用任意新消息或重新绘制冒充发送。

回复完成展开会在最初follow之后改变真实scrollHeight；共同chatMotion的动画收尾必须按最终自然几何再跟随，并尊重此刻的阅读意图、修订和生命周期。不能依赖首页额外的ResizeObserver兜底，否则程序Agent仍漏最后一段；中途上翻、打断或关闭时不得迟到追尾。

共同Markdown表格先按内容和实际字体分配列宽，再在表格内部横滚，不能把所有列强挤进正文宽度。单元格文字最小宽度不包含内边距；全局border-box会侵占它。长单元格仍需有界换行；核少列/多列、长标识符、常用大字、125%和窄窗的真实字形与页面宽度，不能只证明末列可以滚到。

原生frameReady只代表视口布局就绪；portalPresented必须由实际onVisibility(true)单独释放，准备/隐藏时清除。原生窗口绘制确认可早于真正可见，不能因此让Halo在透明body里播放。实际AIDEBUG须把自定义外观、窗口可见性和粒子中间帧放在同一条真实流程验证。

展开前先测量真实输入栏占用，再由原chatMotion在onBeforeOpen按当前following恢复阅读位置，最后测Halo目标；不能把输入栏造成的追尾延后到粒子结束，否则带多段Brief的工作会在终点再跳一个输入栏高度。动画playing期间继续禁止把Halo临时视觉溢出当内容增长；主动回看保持原following=false，不强制追尾。

共同chatMotion必须按消息身份区分入场。新提交的用户行可能暂时是live回调的最后节点，仍只作位置运动，不能沿Agent回复的透明入场；用户原文、头像和名字在实际点击同一事件回合可见，待Core接收时保留同一节点。

fullMessages群聊成员使用共同WorkTranscript和工作阅读区，不走多人概览的单行裁切。成员预览的max-height/overflow只约束非工作摘要，不得覆盖data-work=true的共同滚动规则；最终历史仍自然展开。流式全文已收到不等于末尾可见，要核实际scrollTop与可见读区。

可视化：stage-layout统一工具回执准入与剩余空间策略；准备类工具也可展示，但不改Core执行统计。不要用execution_started、固定半屏或仅模型流phase隐藏真实操作。stage根据侧栏后的空间优先并排、窄窗上下排列；resize也重排，不等新的模型消息。主工程work-preview-user覆盖实际EXE，完成后恢复聊天。

用量详情：查询身份用usageScope的持久会话编号，换当前会话立即使旧异步返回失效。当前累计与顶栏共同消费Core持久统计；明细使用可归属账本，缺口必须说明。全部会话按真实账本列出，不能伪造旧记录归属来凑数。

统一分层聊天：layered-chat持有展开/折叠与动画，program-agent-surface/folded-overlay沿原鉴权和代次投影到原生层；迟到关闭确认不得缩小重新展开的表面。首页由work-surface的tools模式消费当前代次只读工具投影，默认左右双窗，总览最多12窗；终端、搜索、差异复用所属Tool视图，其他场景由Tool/presentation/projection提供。收起/聚焦仅改变呈现，完整回执保留，程序遮罩和模糊实时生效。外部浏览器/电脑/IDE程序投影属于后续独立阶段，不从首页工具视图自动启动。Coding复用共同聊天、计划与report-surface阅读器；过程默认退场，原档案不删除。单行工作状态集中在chat-status，不另开头像上方错误提示。头像保持圆形，主题光圈预览卡才有背景块。

决策共用ask-user问题模型与原RPC，只在现有input-dock向上展开，与唯一主输入共用连续材质；背景工具区不投影ask_user/human，也不在历史另建答复框。多问分页，本地保存选择/自定义回答、推荐或跳过，可返回修改；最后一次确认或Ctrl+Enter才提交当前组。原Core逐问题身份与回执保留，部分确认只重试未确认的原载荷，提交期间新增问题不并入已确认组，切scope立即停止后续派发。普通草稿、附件、粘贴与选区分开保留。原生层复用同一面板，校验完整问题key，输入法期间不提交或强行换编辑内容。工作阅读有界，最终正文自然展开为历史，动效不缩放文字或重播正文。

决策面板展开/收起需连续改变实际占位，不能只淡入内容而让聊天视口一次跳变；内层正文保持原尺寸，快速反向先采当前几何再取消旧通道。退场期间立即inert并从辅助阅读中退出，原输入草稿恢复不等动画；隐藏、减少动效和原生resize提交当前逻辑状态并释放动效。普通快照不重启动画或重写相同文本节点。

借用或恢复多行草稿与附件时，面板和原输入区共同协调占位；只改变输入外层高度，不逐帧改变textarea自然尺寸。逻辑切换前采原几何，两条通道使用同一时间线和缓动，快速反向从当前总占位接续；关闭解包还原同一composer节点。原生层同样在应用新编辑内容前采样，布局完成后再呈现决策。

让位期间实际输入自然高度变化时，用原composer的ResizeObserver从当前几何续接新目标；外层自身动画不触发textarea逐帧调高。结束回调也检查新高度，覆盖输入先于观察器送达的边界，不能释放到过时目标后突然跳高；close断开该观察器。

空普通草稿与空问题回答等高时，面板让位期间同样保留输入外层的固定高度通道，避免自然输入先增长、ResizeObserver稍后才送达而产生同步跳高。共用原续接及finished检查，不为这种情况另写编辑器或逐帧调高textarea。

同一问题的数量、依据或错误等内容更新也可能改变面板布局。重启面板前同时保存正在让位的输入外层当前高度并取消其旧通道，不能给旧输入动画重设startTime而从原起点重播；普通相同快照仍保持原通道。
